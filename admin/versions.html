Release history

One row per release. The version in the nav and footer of every page must match the top row, and the validator checks that it does.

VersionDateWhat changed
v0.4.12026-10-23Uptime checks in every region, twin first. A Node.js 22 Lambda function, one file with no dependencies, that checks websites and appends each report, encrypted as sgit's envelope v2 (RSA-OAEP SHA-256 wrapping AES-256-GCM, decrypted in CI by sgit's own construction), to an sgit append lane; scheduled by EventBridge, invokable with IAM, and through a function URL only with a controller-signed request. New twins: Lambda (running Node.js functions through one harness, with node in CI and the browser's JSPI in the page, and Python in process), IAM roles, EventBridge rules, CloudFront distributions, the sgit append lane and the internet a function reaches. Uptime__Deploy: one boto3 deploy for the twin and the account, to any number of regions. The uptime page and the plan. Versions: a push to dev may only bump the minor, a push to main only the major; v0.4.0, released from dev, was the last exception. Browser tests run on a secure origin.
v0.4.02026-10-21Live, from the browser. The S3 browser goes live with the session pasted in the same tab: directly where AWS allows this site's origin (a bucket with a CORS rule), and through Twin__Relay.py, a one-file local relay that holds no credentials, for what S3 never answers a browser, such as ListBuckets. Read-only unless writes are allowed. How it works, step by step, with diagrams written in Mermaid and rendered to SVG at build time. Least privilege for the twin: four S3 permission sets as policy files, the IAM Identity Center CLI, checked through the AWS CLI in CI (check_cli.py). The article A live AWS session from a browser tab, after the first real session was checked against AWS STS from this site. Three live-path bugs fixed before any real use: chunked uploads hung, uploads went empty, downloads failed.
v0.3.12026-10-21Deployed, and tagged on every release. aws.twin.sgit.ai resolved to GitHub Pages and answered 404, because this repository had no deploy workflow; deploy-pages.yml is now the twins hub's own (validate, tag vX.Y.Z on every push to dev, publish), with this site's tests added to its gate. The version lives in admin/build/version.txt; CNAME, assets/version.js, a markdown twin for every page, sitemap.xml and robots.txt added; the four briefs published in full; BRIEF-CORRECTIONS.md and REALITY.md written; a release script that checks the live site. Also ships 308b2ae, which committed the build scripts a .gitignore rule had hidden. Releases v0.1.0 to v0.3.0 were tagged by hand.
v0.3.02026-10-21The twin moves to Python. aws_twin: S3's REST-XML protocol and STS GetCallerIdentity over a Python mirror of sg-vfs, a botocore hook with twin, live and replay routes, a local endpoint, traffic recording. One test suite, run by pytest in CI and by Pyodide in the browser. OSBot-AWS runs against it unchanged in both. The S3 browser, every button a Python call, persisted through sg-vfs's IndexedDB provider (vendored). AWS sessions: setup, paste and a live check, and measured CORS for the better methods. The article The twin is Python now. CI on GitHub Actions.
v0.2.02026-10-21The articles section, in the newsroom's format: A first go at the AWS twin (the build agent, in its own voice) and boto3 in the browser (Dinis Cruz, from a voice memo: the JavaScript SDK's maturity, boto3 under Pyodide against the twin, and the CORS measurement). The experiments and their data under articles/data/. The team page. Build-state rows updated for what was measured.
v0.1.02026-10-21First release. The site: front page, design, workflow, naming, status, admin. The proof of concept: the interface (8 AWS-shaped namespaces, 42 operations, plus 3 twin-only), the vault backend on localStorage with commits and diff, the memory backend, the live backend's session slot, two deployment templates, the demo estate, the account graph, and the UI. 214 test assertions. Captured the naming decision of the same day: aws.twin.sgit.ai, repo SGit-AI__Website__Twin__AWS, hub twins.sgit.ai.

aws.twin.sgit.ai

The AWS twin: an AWS-shaped interface (S3, Lambda, EC2, IAM, billing, logs) whose backend is a vault, with a live session as one backend among several. One instance in the twins family; the primitive is defined on twins.sgit.ai. All content CC BY 4.0; the code is Apache-2.0.
